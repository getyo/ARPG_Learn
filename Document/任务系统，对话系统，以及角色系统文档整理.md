### 2.1 类图


解释如下：

1. 真正的数据驱动实现在对话资产里面，编辑器里面也是操作对话资产
2. 对话组件本身是对对话子系统的封装，为了让单个角色对话启动时逻辑更清晰。
3. 对话组件不能有下一句这个功能，因为对话系统本身是集中式的设计，下一句不定是组件的Owner，他获取了属于其他人的对话逻辑上不正确。
4. 任务子系统唯一的耦合点在于广播对话完成这一任务目标完成条件

### 2.2 对话系统初始化以及对话资产读取入流程

```mermaid
flowchart

Edit-->ReadDialogue[DialogueSubSystem读入所有对话资产]
ReadDialogue-->Classify[对所有对话资产按照任务，阶段添加到DialogueAssetMap]

```

### 2.3 对话进行流程

```mermaid
flowchart 

Start(开始)-->PlayInteract[玩家与角色互动开始对话]
PlayInteract-->DialogueStart[某个角色的DialogueComponent调用StartDialogue]
DialogueStart-->DialogueSysSt[上述调用转交给DialogueSubSystem并调用同名函数]
DialogueSysSt-->FindDialogue[DialogueSubSystem根据任务，阶段寻找对话资产]
FindDialogue --> HasDialogue?{是否存在所需资产？}
HasDialogue?--是-->DialogueSysSet[对话系统设置当前对话资产相关数据，准备逐句返回对话]
HasDialogue?--否-->End(结束并报错)
DialogueSysSet-->ShowDialogue[UI界面相关逻辑直接与DialogueSubSystem交互逐句显示对话]

DialogueEnd? --是--> EndDialogueTagSet[UI界面设置相关对话结束标签]
DialogueEnd? --否--> ShowDialogue
EndDialogueTagSet --> EndDialogue[开启对话角色检测到对话结束，DialogueComponent调用EndDialogue]
EndDialogue --> DialogueSysEnd[上述调用转交给DialogueSubsystem，并调用同名函数]
DialogueSysEnd --> IsDaily{是否任务相关对话，即判断对话资产的任务ID是否为空（空为非任务对话）}
IsDaily --否--> BoradcastFinish[广播对话完成目标条件（用于任务目标完成）]
IsDaily --是--> ClearCurDialogue[DIalogueSubsystem将所有有关当前对话的内容置空，防止出错]
BoradcastFinish--> ClearCurDialogue
ClearCurDialogue --> End(结束)

```





## 三、任务系统

### 3.1 类图

#### 3.1.1 任务子系统

```mermaid
classDiagram 
	QuestTargetCondition *-- FS_QuestTarget
	KillCondition --|> QuestTargetCondition
	DialogueCondition --|> QuestTargetCondition
```

说明：

1. `QuestTargetCondition`作为纯虚基类而存在，其他目标完成条件都是它的子类
2. `FS_QuestTargetConditionInfo`是你在编辑器真正编辑的东西，在任务初始化阶段会被创建成任务条件加入任务目标数据中，之所以这么做是因为`QuestTargetCondition`受限于多态等原因必须是一个指针，而编辑器无法编辑指针。
3. `FS_QuestTargetData`唯一的作用是作为`GlobalQuestTargetMessenger`的传递参数
4. `BroadcastFinish`其实是封装了`GlobalQuestTargetMessenger`的调用，你当然可以用后者进行某个目标条件完成的广播，但是封装在任务子系统里面显得逻辑更清楚一些。

3. 关于任务的Stage，一般来说设置是：

   - 未开始/玩家未接取为0
   - 接取后为100
   - 之后每个阶段都增加100

4. `QuestRelativeInterface`是用来判断当前Actor是否是任务相关的接口，里面还有一些附带的获取Actor任务的函数

### 3.2 任务系统初始化流程

```mermaid
flowchart
Start(开始)-->SetDB[编辑器中设置存储任务信息的数据表]
SetDB-->QuestSysInit[任务系统开始初始化]
QuestSysInit --> QuestTargetConditionInit[调用InitQuestTargetCondition，从项目配置中读入枚举条件类型到实际条件类型的映射]
QuestTargetConditionInit --> ReadQuest[读取任务数据表格，在此过程根据编辑器内容创建相应的QuestTargetCondition]
ReadQuest --> BindBroadcast[绑定DeliverTargetCheck作为处理函数到GlobalQuestTargetMessenger]
BindBroadcast -->End(结束)
```

### 3.3 任务完成流程

``` mermaid
flowchart
Start(开始)--> BroadCast[某个地方调用QuestSubSystem的BroadCastFinish]
BroadCast --> Deliver[QuestSubSystem开始执行DeliverTargetCheck对到来的广播信息进行分发]
Deliver --> GetQuest{尝试获取广播指定的任务}
GetQuest --是--> IsStage0{广播任务是否还未激活？}
GetQuest --否--> End(结束)
IsStage0 --是--> ConditionPassed{当前目标所有条件是否通过？}
IsStage0 --否--> QuestPush[进入正常的任务推进流程]
ConditionPassed --是--> ActiveQuest[通过PlayerController激活任务]
ConditionPassed --否--> End
ActiveQuest --> End
QuestPush --> HasStage{广播任务是否含有指定阶段？}
HasStage --是--> ConditionPassed0{当前目标所有条件是否通过？}
HasStage --否--> End
ConditionPassed0 --是--> NextStage[将任务推进到下一个阶段]
ConditionPassed0 --否--> End
NextStage --> IsFinished{任务是否结束？}
IsFinished --是--> FinishQuest[设置任务结束]
IsFinished --否--> End
FinishQuest --> End
ConditionPassed0 --否--> End

```

### 3.4 关于任务激活的两种方式

​	我的设计里面，任务激活是有两者方式的：

1. 如果任务的`Stage0`也就是未激活阶段里面没有完成条件，那这个任务必须通过和NPC互动，然后弹出任务界面点击接取按钮才能接取。
2. 如果任务的`Stage0`也就是未激活阶段里面有完成条件，那么当完成条件满足时任务就会自动出现在玩家的任务列表里面

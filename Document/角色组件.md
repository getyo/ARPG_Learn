# 角色组件

## 一、`Character Status`

这个组件负责管理角色的生命、耐力、经验、等级，并在数值变化时驱动对应的 UI 更新。现在的结构是 **C++ 组件 + 蓝图子类**：

1. **C++ 部分**：`Source/FirstRPG/Component/CharacterStatusComponent.h/.cpp`（类 `UCharacterStatusComponent`）持有全部数据与规则，完全不碰 UI。
2. **蓝图部分**：`Content/Component/BPC_CharacterStatus`（父类就是上面这个 C++ 类）只做表现——取 UI 引用、刷进度条与文本。玩家 / NPC / 坐骑的表现差异（受击音效、升级音效等）在自己的蓝图子类里覆写。

### 1.1 数据与规则（C++）

数据（可在细节面板搜索 `Character Status` 标签设置，蓝图只读）：

1. 生命：`CurHealth` / `MaxHealth`

2. 耐力：`CurStamina` / `MaxStamina`，以及只读的 `IsStaminaRunOut`

3. 经验与等级：`CurXP` / `MaxXP` / `Level`，`MaxXPIncrement` 是每次升级提升的经验上限

4. 生死：`IsDead`、`CanBeKilled`（默认可击杀）

规则函数都是 `BlueprintNativeEvent`：蓝图子类可以覆写，覆写里调用 `Parent` 就会落到 C++ 实现，所以原来蓝图的调用点不受影响。

1. `DecreaseHealth(Damage, Is Dead)`：扣血，`Is Dead` 输出是否死亡；越扣到 0 且 `CanBeKilled` 为真时置 `IsDead`。配套还有 `IncreaseHealth` / `PromoteMaxHealth`。
2. `DecreaseStamina(…, Is Stamina Run Out)`：扣耐力并回传是否耗尽；配套 `IncreaseStamina` / `PromoteMaxStamina`。
3. `IncreaseXP(Xp)`：返回是否升级（升级会扣掉一次经验上限并升一级）；`IncreaseLevel` 单独提升等级与经验上限。
4. `CharacterDie()`：返回 `IsDead`，供角色 / AI 判断死亡。

事件（蓝图可绑定）：`OnHealthChanged`、`OnStaminaChanged`、`OnXPChanged`、`OnLevelChanged`、`OnDeath`、`OnRevive`、`OnStaminaRunOut`。

### 1.2 状态UI相关的设置

一个角色类如果想利用`Character Status`组件进行UI同步更新，需要实现`BPI_Status`接口。接口定义如下：

<img src="image-20260424085116683.png" alt="image-20260424085116683" style="zoom:50%;" />

总的来说就是把提示文本和进度条交给`Character Status`即可，如果你没有某一个的话就不实现对应函数即可，`Character Status`自己会进行有效性检测，无效对象不会更新也不会报错。

**时序上有两点要注意：**

1. 组件的 `BeginPlay` **不驱动 UI**：组件的 `BeginPlay` 早于 Owner 角色的 `BeginPlay`，此时角色还没 `CreateWidget`，提前刷新只会读到空引用。所以组件在 `BeginPlay` 只广播一次数值事件。
2. **由角色在建好控件后通知组件**：角色在 `CreateWidget` / `AddToViewport` 之后调用组件的 `ResetStatusUI`（玩家角色已经这么做）。之后每次数值变化，C++ 会调用 `UpdateStatusUI`（蓝图实现事件），蓝图在这个事件里刷新表现。

蓝图内部两个函数的分工：

1. `FetchStatusUI`：`Cast Owner -> BPI_Status`，把 5 个引用（血条 / 血文本 / 耐力条 / 等级文本 / 经验条）取出来存进组件变量，最后在血条有效时转交 `RefreshStatusUI`。
2. `RefreshStatusUI`：用 `Sequence` 分 5 条并行分支，每条分支都是「取数 → `IsValid` → 动作」——3 条进度条走 `SetPercent`（当前值 / 上限），血文本走 `FormatText "{0}/{1}"`、等级文本走 `FormatText "LV:{0}"`。某一条无效只会跳过它自己，不影响其它分支。

> 小提示：血量是浮点数，直接喂 `FormatText` 会带小数点和尾零；只想显示整数的话，在取数后面接一个 `Round`（四舍五入）/ `Floor` / `Truncate` 再喂进去即可。

但是需要注意，`Character Status`真的只负责更新进度条和提示文本，你的UI放在角色脑袋上还是屏幕空间，这些要由角色自己决定，因为不同角色需求不同。对于`AICharacter`的`Status Widget`，它默认放在角色头顶，只显示血条，如果你需要更改可以去对应蓝图修改。（目前 NPC 侧只有「死亡时隐藏它」这一步，还没有创建控件与喂数据的链路，NPC 血条要动起来需要补这一段。）

## 二、`Action Manager`

​	这个组件的目的是进行动作优先级和打断的管理，举个例子：角色在疾奔的时候不能瞄准射箭，角色在挨打的时候不能攻击。

### 2.1 `CanExe`与`End Action`

`Action Manager`向外暴露的主要接口就是两个函数，就如同名字一样，他们的函数签名如下：

<img src="image-20260424085903993.png" alt="image-20260424085903993" style="zoom:50%;" />

第三个函数`PrintAllActiveAction`用来输出当前所有正在进行的动作，主要用于调试，和功能实现无关。另外还有一个纯查询函数`IsActiveAction`，用于判断某个动作当前是否正在进行中。

`CanExe`和`EndAction`的输入都为一个Tag，这个Tag在`Character.Action`层级之下，你可以选择对应的Tag，如果要**新增Tag**，**2.2节**有详细介绍。

`CanExe`返回的是当前动作能否执行，并且会把动作加入进行动作集合，当前动作只有能够打断所有进行动作才能执行，蹲下的时候不能疾奔，走路的时候能疾奔，那么蹲下走路时就不能疾奔。实际运用是你需要在`CanExe`后面跟一个`Branch`节点判断，动作不能执行不要播放相关动画或者转化动画蓝图的状态。

每一个动作结束之后，必须调用`End Action`节点把它从进行动作集合中移除，否则这个动作永远不会移除，如果是攻击这种高优先级动作在动画播放完之后没有移除，那么几乎所有的角色动画行为都会被卡住。

我提供的抽象角色父类已经设置好了大部分通用行为，例如：移动，死亡，攻击，受击。你如果有需要，可以根据自己的需求新增，但是必须遵循`CanExe`和`EndAction`的配套使用。

### 2.2 新增动作Tag

你如果要新增动作Tag，有以下两步操作：

1. 到`Content\Player\Blueprints\ActionInterrputAndPoiseSystem`之下，打开`DB_CharacterActionTag`，新加入你要添加的动作Tag，注意命名格式统一为`Character.Action.***`
2. 同一目录下打开`DB_ActionInerrputTable`设置哪些动作能够打断你新添加的动作：
   - 创建新行，行名字就是你的`***`动作。
   - 设置该行`ActionTag`为你第一步添加的Tag
   - `CanBeInterrput`数组为可以打断你这个动作的动作Tag集合，你添加对应Tag即可

## 五、`Dialogue`

对话组件本质是对对话系统调用接口的封装，不过你最好不要随便绕过对话组件去调用对话系统，因为我不保证这个操作的安全性，对话系统有兴趣可查看相关文档，也在同一目录下，这一章之说对话组件对外暴露的接口和用法。

对话组件不需要进行任何额外设置，也没有留给你设置的余地，它的功能就是播放对话。接口如下：

```c++
//查看角色是否在对话中
UFUNCTION(BlueprintCallable,BlueprintPure, Category = "Dialogue")
inline bool IsInDialogue() const;
//根据任务以及节点播放对话
UFUNCTION(BlueprintCallable, Category = "Dialogue")
bool StartDialogue(const FGameplayTag &QuestTag,const int Stage,AThirdPersonPlayerController* PlayerController);
//结束当前对话
UFUNCTION(BlueprintCallable, Category = "Dialogue")
void EndDialogue();
```

就具体实现来讲，对话组件的使用其实和对话窗口紧密耦合的，对话组件负责告诉对话窗口要播放哪个对话，对话窗口的`Play Dialogue`来一步步播放下一个对话。但是这个你不需要操心，只需要设置好`Quest`组件里面的`Focused Quest Tag`即可，因为对话组件会根据角色的聚焦来确定播放哪段对话，具体任务进度不是NPC设置的而是从玩家控制器读取的。详情见任务系统的文档。
## 六、关于存档

各组件本身不直接参与存档，存档的入口在角色本体（ICharacterSaveInterface）与物品（IItemSaveInterface）上，角色/物品会在BeginPlay时自动注册到USaveLoadSystem。需要存档的数据通过接口传入结构体，具体设计见**存档系统.md**。

其中 `UEquipmentComponent` 在存档链路中是**可选依赖**：`AGeneralCharacter` 读写存档时若找不到该组件，只跳过装备状态部分（其余字段照常读写），因此马、象、动物这类没有装备组件的角色也能正常存档/读档。
